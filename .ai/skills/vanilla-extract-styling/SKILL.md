# Vanilla Extract Styling Enforcement Skill

This skill enforces Vanilla Extract as the sole styling engine across all applications and libraries in accordance with ADR 014 (Styling Engine) and ADR 011 (CSS Architecture and Theming).

## 1. Prohibited Styling Frameworks & Engines

Agents are strictly forbidden from introducing, importing, or configuring alternative styling frameworks or runtime CSS-in-JS engines:
- **Banned:** Tailwind CSS (utility classes, directives like `@apply`, `@tailwind`).
- **Banned:** CSS Modules (`*.module.css`).
- **Banned:** Runtime CSS-in-JS libraries including Emotion (`@emotion/react`, `@emotion/styled`) and styled-components.
- **Banned:** Inline style objects (`style={{ ... }}`) for static component styling (reserved strictly for purely dynamic, runtime-computed values such as animation coordinates or progress bars).

## 2. Component Styling Declarations (`.css.ts`)

- All styles must be declared strictly in sibling `.css.ts` files using `@vanilla-extract/css`.
- Rely on core Vanilla Extract primitives:
  - `style()` for individual classes and static element styling.
  - `styleVariants()` for multi-variant component states (e.g., variants, sizes, visual intents).
  - `globalStyle()` strictly when targeting external resets or container-level overrides.
- **File Pairing Standard**: A component file (e.g., `Button.tsx`) must define its styles in an adjacent file named `Button.css.ts` and import the generated class names directly.

## 3. Theme Variables & Color Token Consumption

- **Zero Hardcoded Colors**: Agents must never hardcode hex color values (`#ffffff`, `#000000`), raw RGB/HSL values, or raw `oklch(...)` strings directly inside component `.css.ts` files.
- **Themeset Variables**: All visual tokens (colors, background surfaces, text colors, border highlights) must import and consume CSS Custom Properties generated by the Themeset contract.
  - Consume tokens either via standard CSS custom properties:
    ```ts
    import { style } from '@vanilla-extract/css';

    export const card = style({
      backgroundColor: 'var(--color-surface)',
      color: 'var(--color-text)',
      borderColor: 'var(--color-border)',
    });
    ```
  - Or via designated TypeScript theme contract utilities provided by the design system.
- In accordance with ADR 011, the design system utilizes `oklch` and `light-dark()` at the root level; consuming semantic variables guarantees seamless support for dark mode and high-contrast modes (`@media (prefers-contrast: more)`).

## 4. CSS Units Constraint (Prefer `rem`)

In accordance with `.ai/rules.md` (Section 5):
- **Prefer REM**: Always use `rem` units for typography (`font-size`, `line-height`), spacing (`margin`, `padding`, `gap`), and dimensions (`width`, `height`, `max-width`, `min-height`).
- **Prohibited PX**: Do not use `px` units except for:
  1. Media queries (where `px` or `em` is standard).
  2. Border widths (e.g., `1px solid ...` to preserve pixel-level sharpness).
  3. Strict accessibility minimums (e.g., `24px` by `24px` minimum interactive touch targets per WCAG 2.2 AA).

## 5. Self-Documenting Style Contracts & Comments

- **Semantic Class & Variant Identifiers**: Style classes, variant keys, and recipe definitions must be named descriptively (e.g., `primaryActionButton`, `compactBoardGrid`).
- **Concise Styling Comments**: Add brief, focused comments when declaring non-obvious CSS calculations, intricate media queries, or specificity overrides. Avoid redundant comments for standard visual properties.
