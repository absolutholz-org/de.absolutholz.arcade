# Theme Architecture

Our design system utilizes a modern, white-labelable **two-tier theme layout strategy** powered by CSS Custom Properties and native `light-dark()` OKLCH color spaces. This strategy achieves high visual flexibility with zero runtime JavaScript cost.

---

### The Two-Tier Strategy

Our architecture operates in three logical steps:

1. **Global Brand Themesets (Tier 1)**
   These define raw brand palettes flat on the `:root` element.
   * *Standard Brand:* Defines `--theme-primary-surface: light-dark(oklch(0.98 0.005 250), ...)`
   * *Christmas Brand:* Defines `--theme-primary-surface: light-dark(oklch(0.97 0.015 140), ...)`

2. **Component Theme Context (Tier 2)**
   A React `<Theme>` component maps generic variables to the active brand tokens for that DOM tree.
   * `<Theme name="primary">` maps `--color-surface` to `var(--theme-primary-surface)`
   * `<Theme name="secondary">` maps `--color-surface` to `var(--theme-secondary-surface)`

3. **Generic App API (Functional Tokens)**
   Your components read these generic variables.
   * A Card component always styles its background with `var(--color-surface)`, completely unaware of which brand or sub-theme is active.


### 1. Tier 1: Themesets (Global Brand Layers)
Themesets act as static, global layers representing a specific brand identity or season. Each themeset defines concrete CSS color slots flat on the `:root` level. 
For instance, the **Standard Themeset** initializes cool slate grays and tech-blue accents, while the **Christmas Themeset** registers warm forest greens and berry reds.

### 2. Tier 2: Themes (Contextual Containers)
Themes represent the functional context of a user interface section (e.g. `Primary`, `Secondary`, `Contrast`, or `Accent`). Wrapping a component tree with the React `<Theme>` component (e.g., `<Theme name="secondary">`) maps the global generic functional variables (`--color-surface`, `--color-text-1`, etc.) to the respective flat themeset tokens.

This structure allows the same component code to contextually transform its appearance based on the parent context component and the loaded brand stylesheet.
